🚀 เริ่มใช้ใน 3 ขั้น 🔑 การยืนยันตัวตน 📚 Endpoint ทั้งหมด GET /meta GET /items GET /items/{no} GET /items/{no}/history GET /summary 🎫 Scopes ⚠️ รูปแบบ Error ⏱️ Rate limit 💬 ถามแบบ Vibe คืออะไร 🤖 ต่อกับ AI Agentic n8n Claude Custom GPT / OpenAI LINE Bot 🔗 เชื่อมกับแอปอื่น 🛡️ ความปลอดภัย ❓ คำถามที่พบบ่อย

External Read API เปิดให้ระบบภายนอก (n8n, LINE bot, Claude, สคริปต์ของทีม ฯลฯ) อ่านสถานะ ITGR ได้โดยตรง ไม่ต้องมีคนเปิดเว็บแล้วมานั่งกรองเอง — อ่านอย่างเดียว ไม่มีสิทธิ์เขียนหรือแก้ไขข้อมูลใด ๆ ใช้ token แยกจากระบบ PIN login ของแดชบอร์ดโดยสิ้นเชิง จะรั่วหรือหลุดก็เพิกถอนได้ทันทีโดยไม่กระทบผู้ใช้คนอื่น

✓ Read-only Bearer token ไม่ต้องใช้ API key ของ LLM รองรับ TH/EN

🚀 เริ่มใช้ใน 3 ขั้น

1
ขอ token จาก Admin

ให้ admin เข้า แท็บ Admin → External Read API — Tokens ในแดชบอร์ด แล้วออก token ให้ — ค่า token แสดงได้ครั้งเดียวตอนสร้าง เก็บให้ดี

2
ยิง /meta ครั้งแรก

ดึง /api/v1/meta เพื่อรู้ว่ามีหมวด/สถานะ/พารามิเตอร์อะไรบ้าง — endpoint นี้คือกุญแจของการถามแบบ Vibe

3
ถามคำถามจริง

กรองด้วย /items หรือดูตัวเลขสรุปด้วย /summary

# Base URL
https://itgrmrbn.vercel.app/api/v1

# ทดสอบว่า token ใช้ได้ไหม
curl -H "Authorization: Bearer itgr_live_xxxxxxxxxxxxxxxxxxxxxxxx" \
  https://itgrmrbn.vercel.app/api/v1/meta

🔑 การยืนยันตัวตน

ทุก request ต้องแนบ header Authorization: Bearer <token>

curl -H "Authorization: Bearer itgr_live_xxxxxxxxxxxxxxxxxxxxxxxx" \
  https://itgrmrbn.vercel.app/api/v1/summary
  • Token นี้คนละระบบกับ PIN login ของแดชบอร์ด — ใช้แทนกันไม่ได้ทั้งสองทาง
  • Token ไม่หมดอายุเองโดยดีฟอลต์ จนกว่า admin จะตั้งวันหมดอายุหรือกดเพิกถอน
  • ไม่มีการส่ง CORS header ใด ๆ — เรียกจาก JavaScript ในเบราว์เซอร์ของเว็บอื่นไม่ได้ (ป้องกัน token หลุดผ่านหน้าเว็บ) ใช้ได้จากฝั่งเซิร์ฟเวอร์/สคริปต์/เครื่องมือ automation เท่านั้น
  • ทุก request ถูกบันทึกไว้ (ใครเรียก endpoint ไหน เมื่อไหร่ ผลลัพธ์อะไร) — admin ตรวจสอบย้อนหลังได้

GET/api/v1/meta

ไม่ต้องมี scope เฉพาะ — token ที่ยัง active ใช้ได้เลย เป็นจุดเริ่มต้นเสมอเมื่อเชื่อมระบบใหม่ ผลลัพธ์ cache ได้ 1 ชั่วโมง

คืนข้อมูลทุกอย่างที่ต้องรู้เพื่อประกอบ request เอง: รายชื่อ 8 หมวด (TH/EN), สถานะที่เป็นไปได้, ระดับความเสี่ยง, ประเภทคำถาม, เกณฑ์เกรด, และ ตัวอย่างคำถามภาษาคนคู่กับ URL ที่ควรยิง — นี่คือสิ่งที่ทำให้ AI ภายนอกใช้ API นี้ได้โดยไม่ต้องมีคนเขียน mapping ทีละคำถาม

🎫 Scopes

Token แต่ละใบมีสิทธิ์แยกเป็นชิ้น ๆ — ไม่ใช่ all-or-nothing เลือกได้ตอนออก token ในแท็บ Admin

Scopeให้สิทธิ์อะไรค่าเริ่มต้น
items:readอ่านรายการและรายละเอียดข้อกำหนด (/items, /items/{no})✓ ติดมาให้
summary:readอ่านตัวเลขสรุป/ความคืบหน้า (/summary)✓ ติดมาให้
history:readอ่านความเห็นและไทม์ไลน์ workflow (/items/{no}/history)ต้องขอเพิ่ม

ให้เท่าที่จำเป็นเสมอ — ถ้าเครื่องมือของต้นแค่ต้องรายงานความคืบหน้า ไม่ต้องมี history:read เลย

⚠️ รูปแบบ Error

ทุก error ตอบกลับรูปแบบเดียวกัน มี code ให้เช็คด้วยโปรแกรมได้ ไม่ต้อง parse ข้อความ

{ "error": { "code": "invalid_filter", "message": "\"status=Bogus\" is not a valid value for status.",
             "param": "status", "allowed_values": ["Not Started","In Progress","Compliant","Partial","Not Compliant"] } }
HTTPcodeความหมาย
400invalid_filter / invalid_item_noพารามิเตอร์ผิด — ดู allowed_values ประกอบ
401missing_token / invalid_token / token_expiredไม่มี header, token ผิด, ถูกเพิกถอน, หรือหมดอายุ
403insufficient_scopetoken ไม่มี scope ที่ endpoint นี้ต้องการ (ดู required_scopes)
404item_not_foundไม่มีข้อกำหนดเลขนี้ (มีแค่ 1–96)
429rate_limitedยิงถี่เกินไป — ดู header Retry-After
500internal_errorฝั่งเซิร์ฟเวอร์มีปัญหา ลองใหม่ได้ ถ้าเกิดซ้ำแจ้ง admin

⏱️ Rate limit

จำกัด 60 requests/นาที ต่อ token เกินแล้วได้ 429 พร้อม header Retry-After: 60

ถ้าทำ automation ที่ต้องดึงข้อมูลบ่อย ๆ (เช่นเช็คทุกนาที) แนะนำใช้ updated_since ใน /items แทนการดึงทั้งหมดซ้ำทุกครั้ง

💬 ถามแบบ Vibe คืออะไร

API นี้ไม่มี AI ของตัวเอง — ไม่ต้องมีก็ได้ เพราะ /meta ให้ข้อมูลพอที่ LLM ฝั่งที่เรียกใช้ (Claude, GPT, หรือโมเดลไหนก็ได้) แปลงคำถามภาษาคนเป็น query เองได้ทันที นี่คือตัวอย่างจริงที่เพิ่งทำให้ดูตอนทดสอบระบบ:

1
คำถามจากคน: "หมวดไหนยังแดงอยู่บ้าง"
2
AI เช็ค /meta — เห็นว่า "แดง" ใน context นี้แปลว่า risk สูงและยังไม่เริ่ม จากตัวอย่างคำถามที่ /meta ให้มา
3
AI ประกอบ request เอง:
GET /items?risk=Very High&status=Not Started
4
ตอบกลับเป็นภาษาคน: "มี 28 ข้อที่ความเสี่ยงสูงมากและยังไม่เริ่มทำเลย เช่นข้อ 1 การจัดทำระเบียบความมั่นคงปลอดภัยด้าน IT..."

ต้นไม่ต้องเขียนโค้ด mapping "แดง" → risk=Very High เอง — AI ที่อ่าน /meta แล้วเดาความหมายจากตัวอย่างคำถามได้เลย ยิ่งคำถามซับซ้อนเท่าไหร่ ยิ่งเห็นประโยชน์ของแนวทางนี้

🤖 ต่อกับ AI Agentic

⚙️ n8n

  1. เพิ่ม node HTTP Request
  2. Method: GET, URL: https://itgrmrbn.vercel.app/api/v1/summary
  3. Authentication → Generic Credential Type → Header Auth → สร้าง credential ใหม่: Name = Authorization, Value = Bearer itgr_live_...
  4. ถ้าจะให้ AI Agent node ใน n8n ตัดสินใจเองว่าจะเรียก endpoint ไหน ให้ดึงผล /meta มาใส่ใน system prompt ของ AI Agent node ก่อน แล้วให้มันสร้าง URL เองตามตัวอย่าง
  5. ต่อผลลัพธ์เข้า node ส่ง LINE/Slack/อีเมล เพื่อทำเป็นรายงานประจำวันอัตโนมัติได้เลย

✳️ Claude (Claude Code / Projects / Custom instructions)

วิธีที่ตรงที่สุด: บอก Claude ตรง ๆ ว่ามี API นี้อยู่ พร้อม token แล้วให้มันดึง /meta เอง — Claude ที่มีเครื่องมือเรียกเว็บ (เช่น WebFetch) ประกอบ query และสรุปคำตอบให้เป็นภาษาคนได้ทันที เหมือนตัวอย่างในหัวข้อ "ถามแบบ Vibe" ด้านบน ซึ่งเป็นวิธีที่ใช้ทดสอบ API ชุดนี้เองจริง ๆ ตอนพัฒนา

// ตัวอย่าง prompt ที่ใช้ได้เลย
"เรียก GET https://itgrmrbn.vercel.app/api/v1/meta
ด้วย Authorization: Bearer itgr_live_xxxxx แล้วบอกฉันว่าตอนนี้
หมวดไหนของ ITGR ยังมีข้อความเสี่ยงสูงมากที่ยังไม่เริ่มทำบ้าง"

🧩 Custom GPT / OpenAI Function Calling

ยังไม่มีไฟล์ openapi.json ให้ import อัตโนมัติ (อยู่ในแผนถัดไป) — ระหว่างนี้ทำได้ 2 ทาง:

  • ทางลัด: วางผลลัพธ์ของ /meta ทั้งก้อนไว้ใน system instructions ของ Custom GPT แล้วสอนให้มันเรียก endpoint ผ่าน Actions ด้วย base URL + Bearer auth
  • ทางที่ยืดหยุ่นกว่า: ประกาศ 1 action แบบ generic (path/query เป็น parameter) แล้วให้โมเดลกรอกเองตามที่เรียนรู้จาก /meta

💚 LINE Bot

LINE bot เองไม่มี Vibe-parsing ในตัว — วิธีที่ตรงไปตรงมาที่สุดคือให้ webhook ของ LINE ส่งข้อความผู้ใช้ต่อไปให้ LLM (ผ่าน n8n หรือ Cloud Function) พร้อมแนบผล /meta เป็น context จากนั้นให้ LLM เรียก External Read API แล้วส่งคำตอบกลับ LINE — จริง ๆ แล้ว pattern นี้เหมือนกับ n8n ด้านบนทุกประการ เพียงแค่ trigger เป็น LINE webhook แทน cron

🔗 เชื่อมกับแอปอื่น (ไม่ใช่ AI)

API นี้เป็น REST ธรรมดา (GET + JSON) — เครื่องมือไหนที่ยิง HTTP request พร้อมใส่ header ได้ก็ใช้ได้หมด ไม่จำเป็นต้องเป็น AI:

  • Google Sheets / Apps Script — UrlFetchApp.fetch() ดึงข้อมูลเข้าสเปรดชีตตามรอบเวลา
  • Make (Integromat) / Zapier — module "HTTP" หรือ "Webhooks" ตั้ง Header Authorization เหมือน n8n
  • Power BI / Looker Studio — เชื่อมเป็น Web/REST data source เพื่อทำ dashboard เพิ่มเติม
  • สคริปต์ของทีมเอง (Python/Node) — ดูตัวอย่างโค้ดด้านล่าง
JavaScript / Node.js
const res = await fetch(
  'https://itgrmrbn.vercel.app/api/v1/summary',
  { headers: { Authorization: 'Bearer ' + TOKEN } }
);
const data = await res.json();
console.log(data.overall.progress_pct);
Python
import requests
r = requests.get(
  "https://itgrmrbn.vercel.app/api/v1/summary",
  headers={"Authorization": f"Bearer {TOKEN}"}
)
print(r.json()["overall"]["progress_pct"])

🛡️ ความปลอดภัย

  • อย่า commit token ลง git หรือวางในที่สาธารณะ — เก็บใน environment variable / credential store ของเครื่องมือที่ใช้เสมอ
  • Token ไม่หมดอายุเอง — ถ้าเลิกใช้เครื่องมือไหนแล้ว ให้เข้าไปกดเพิกถอนที่แท็บ Admin ทันที อย่าปล่อยค้าง
  • ให้ scope เท่าที่จำเป็น — ส่วนใหญ่ไม่ต้องมี history:read
  • ถ้าสงสัยว่า token หลุด กด Revoked ก่อนแล้วค่อยสืบสวน — เพิกถอนมีผลทันที ไม่ต้อง deploy
  • API นี้ อ่านอย่างเดียว ต่อให้ token หลุดก็แก้ไข/ลบข้อมูลอะไรในระบบไม่ได้

❓ คำถามที่พบบ่อย

ทำไม token ของฉันได้ 403 ตลอด?

เช็ค error.required_scopes ใน response — token ใบนั้นอาจไม่มี scope ที่ endpoint ต้องการ (พบบ่อยกับ /items/{no}/history ที่ต้องมี history:read เพิ่ม) ให้ admin เพิ่ม scope จากแท็บ Admin

แก้ owner/note/status ผ่าน API นี้ได้ไหม?

ไม่ได้ — API นี้อ่านอย่างเดียวโดยตั้งใจ การแก้ไขและ workflow อนุมัติต้องทำผ่านแดชบอร์ดโดยคนจริงเท่านั้น

ทำไม response ใช้เวลานานกว่าที่คิด?

ทุก request บันทึกลง audit log ก่อน ส่งผลลัพธ์กลับเสมอ (ตั้งใจออกแบบให้เป็นแบบนี้เพื่อไม่ให้การบันทึกหลุดหาย) เพิ่มเวลาราวหลักสิบมิลลิวินาที ถือว่าคุ้มกับการมี audit trail ที่ครบ 100%

ดาวน์โหลดไฟล์หลักฐานผ่าน API นี้ได้ไหม?

ไม่ได้ — /items/{no}/history บอกแค่ชื่อไฟล์ ไม่มีลิงก์ดาวน์โหลด ต้องเข้าแดชบอร์ดแล้วล็อกอินด้วย PIN เพื่อดูไฟล์จริง

ต้อง scope อะไรบ้างถ้าจะทำแดชบอร์ดสรุปภาพรวมอย่างเดียว?

summary:read อย่างเดียวก็พอ ไม่ต้องมี items:read เลยถ้าไม่ต้องดูรายข้อ
